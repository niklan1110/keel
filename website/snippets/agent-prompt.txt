This app uses Keel as its backend. Keel is a self-hosted backend that speaks the Supabase APIs: Postgres with a REST API (PostgREST), Auth, Storage, Realtime and Edge Functions (Deno). It runs on my own server, not on supabase.com.

## Connection
- API URL: http://YOUR-SERVER:8000/my-app (project "my-app"; the /my-app path is part of the URL, keep it)
- Anon key (public, safe in browser and mobile code): YOUR_ANON_KEY
- Keel docs: http://YOUR-SERVER:8000/docs. For you: http://YOUR-SERVER:8000/docs/llms.txt (index of pages as Markdown) and http://YOUR-SERVER:8000/docs/llms-full.txt (all docs in one file).
- Optional server-side secrets, which I add to the project's .env myself (gitignored). Never print them, commit them or put them in client code:
  - KEEL_SERVICE_ROLE_KEY: bypasses row level security; only for server code, scripts and edge functions.
  - KEEL_DB_URL=postgresql://my_app_owner:PASSWORD@YOUR-SERVER:5432/my_app?sslmode=require: the project's owner role, for migrations, type generation and deploying functions. It owns the public schema and can change auth, storage and realtime data, but isn't a superuser.

## Before writing code
Download the docs once (for example `mkdir -p .keel && curl -s http://YOUR-SERVER:8000/docs/llms-full.txt -o .keel/docs.md`, and add .keel/ to .gitignore) and read the sections you need. If you can't reach the server, ask me to save that file into the project. Supabase guides and examples apply unless the Keel docs say otherwise. Use the API URL above wherever they use https://<ref>.supabase.co.

## Rules
1. Client: @supabase/supabase-js v2, `createClient(KEEL_URL, KEEL_ANON_KEY)`, with both values read from env vars (VITE_/NEXT_PUBLIC_/EXPO_PUBLIC_ prefixes as the framework needs). Flutter, Swift, Kotlin and Python Supabase clients take the same values.
2. Schema: write every change as a SQL migration file in supabase/migrations/ (named <timestamp>_<name>.sql) and apply it with `psql "$KEEL_DB_URL" -v ON_ERROR_STOP=1 -f <file>`. Without psql, use `docker run --rm -i postgres:17-alpine psql "$KEEL_DB_URL" -v ON_ERROR_STOP=1 < <file>`. (Inside `docker run`, a localhost address means the container itself: if Keel runs on this machine, use host.docker.internal on macOS and Windows, or add --network host on Linux.) Without KEEL_DB_URL, give me the SQL to run in Keel Studio's SQL editor. Don't use Supabase cloud commands (supabase link, supabase db push, supabase functions deploy): there is no Supabase project.
3. Row level security is switched on automatically for every new table in the public schema. With no policy, the anon key and signed-in users can't read or write the table. Add policies in the same migration (auth.uid(), auth.jwt(), roles anon and authenticated). Only the service role key bypasses RLS.
4. Auth: keel.auth supports email and password, magic links and email codes, phone SMS codes, OAuth with GitHub, Google, Discord, GitLab and Microsoft (provider 'azure') or an OpenID Connect provider I add (provider 'custom:<id>'), anonymous sign-in and MFA (TOTP and phone, aal2 in the JWT). Keep per-user data in public tables keyed by auth.users(id). Create rows for new users with a security definer trigger on auth.users. Sign-in methods, OAuth keys, SMTP and SMS providers are set by me in Studio (Users > Sign-in settings): tell me what to turn on.
5. Storage: keel.storage. Create buckets in a migration (`insert into storage.buckets (id, name, public) values (...)`) and write policies on storage.objects, for example `(storage.foldername(name))[1] = auth.uid()::text` for per-user folders. Resumable (TUS) uploads and image transforms are available.
6. Realtime: `keel.channel(...)` with postgres_changes, broadcast and presence. A table only streams changes after `alter publication supabase_realtime add table <table>;` (add `alter table <table> replica identity full;` to get old rows on update and delete). Use private channels (`config: { private: true }`) with RLS policies on realtime.messages for anything user-specific.
7. Edge functions: TypeScript in supabase/functions/<name>/index.ts using Deno.serve, with shared code in supabase/functions/_shared/. SUPABASE_URL, SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY are set at runtime. A valid JWT is required unless the function is deployed with --no-verify-jwt (use that for webhooks and verify their signatures yourself). Deploy from this project folder with:
   `docker run --rm -e KEEL_DB_URL="$KEEL_DB_URL" -v "$PWD/supabase/functions:/src/functions:ro" @@IMAGES@@/keel:latest fn deploy <name> --project my-app`
   Set function secrets with the same command, replacing `fn deploy <name>` with `secrets set NAME=value`. Without KEEL_DB_URL or Docker, tell me what to deploy: I can paste functions into Studio > Functions.
8. Types: `npx supabase gen types typescript --db-url "$KEEL_DB_URL" --schema public > src/database.types.ts` (needs Docker), then `createClient<Database>(...)`.
9. Also available, as on Supabase: scheduled jobs with pg_cron's API (`cron.schedule`), HTTP requests from SQL and database webhooks with pg_net's API (`net.http_post`, `supabase_functions.http_request` triggers), and the pgvector extension (`create extension if not exists vector with schema extensions`). Put jobs and webhook triggers in migrations; they need the owner role in KEEL_DB_URL. PostGIS is installed too, but I have to enable it once in Studio's SQL editor. Not available in Keel: GraphQL (pg_graphql), Vault, Queues (pgmq), the S3 protocol, SAML/SSO, passkeys, and OAuth providers other than the ones in rule 4 (such as Apple or Slack). Choose an alternative and tell me.
10. Starting data the app needs (categories, plans, example content) goes in a migration with `on conflict do nothing`. Once it's in the database, have me save it as the project's defaults (Studio > Project settings > Defaults > Save current data as defaults), so I can go back to it with Restore defaults.
11. When you finish a change, list for me: migrations to apply, functions to deploy, secrets to set, and Studio settings to change.
